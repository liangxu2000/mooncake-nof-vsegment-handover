# 第四阶段时延测试结果（逐单条件 + 结果）

- 只收录**跑了端到端时延测试**的单：NOF-113R（单 target 背景）、NOF-116、NOF-117、NOF-124、NOF-125。
- **只放读时延，不放写入性能**；每单先写**测试条件**，再放**结果**；时延单位 µs，W9 单位 ns（target 侧每 IO 执行窗口）。
- 写入墙探针（NOF-115/118/119A/120–123）不属时延测试，不在本文，见 `oplog写入墙跟踪.md`。

## 一览（只列 P50）

| 单 | 场景 | vseg P50 | plain P50 | 比值 vseg/plain |
|---|---|---|---|---|
| NOF-113R | 单 target、400 keys、128K | 546.36 | 270.52 | 2.04× |
| NOF-116 | 双 target、400 keys、128K | 323.59（均值） | 266.36 | 1.215×（中位 1.109×） |
| NOF-117 | 双 target、400 keys、**64K** | 286.91（均值） | 266.36 | 1.077×（中位 ~1.10×） |
| NOF-124 | 双 target、**60k keys**、128K、extent 50GiB | **246.32** | **255.06** | **0.966×（parity）** |
| NOF-125 | 双 target、60k keys、128K、extent **256GiB** | 272.37 | 255.06（跨会话） | 1.068×（未达 ≤1.05） |

## 共用口径（所有单相同，除非单内另注）

| 项 | 值 |
|---|---|
| 拓扑 | reader/writer **node2**；master+etcd **node4**；plain 只用 target B（node4）；vseg 用 target A（node3）+ B（node4），`member_count=2` |
| target | 两 target 均 11 盘 RAID0、strip 256KiB、nsid1、端口 4457 |
| key / 数据 | 4MiB/key；400 keys（113R/116/117）；60,000 keys（124/125） |
| 读取并发 | **T1 = threads=1 / batch=1**（应用层一次一个 4MiB get） |
| 链路并发 | `qpairs=4`；plain 每 key 32×128KiB→单 target；vseg 每 key 2×2MiB child，每 target 16×128KiB（64K 臂为 32） |
| 其他 | warmup=128、verify=false、diag 关、sequential |
| vseg 配置 | `member_count=2 / stripe=2MiB / required_medium=nof / reserved_ratio=0 / io_alignment=4096 / submaster_count=1`；extent 见各单 |
| `--num_keys` | vseg 是**每 segment**：400 keys 用 200，60k 用 30,000 |
| 指标 | 端到端 Min/Avg/P50/P90/P99/Max；W9 = target 每 IO 执行窗口，**不是端到端** |
| 验收 | vseg P50 与 W9 均 ≤ plain×1.05；2× 不可接受 |

## NOF-113R（单 target · 400 keys · chunk 扫描）

**测试条件**

- 环境：reader node2；master+etcd node4；**只有 target B（node4，旧实例 2142228）**。
- 数据：400 keys × 4MiB 已存在；vseg `vseg_nof107`（单 target、extent=50GiB、member_count=1）；plain 同 400 keys。
- 负载：T1、warmup=128、qpairs=4、verify=false、diag 关；每臂 3 遍。
- 变量：`MC_NOF_SUBMIT_CHUNK_BYTES` = 128K / 512K / 1M / 2M；vseg 与 plain 读同一 LBA、同 IO 数。
- 链路：单 target；plain 与 vseg 每 key 32 个子 IO（128K 时）。

**结果（T1，3 遍均值，µs）**

| 臂 | chunk | P50 | target W9 | target n/遍 |
|---|---|---|---|---|
| plain | 128K | **270.52** | 120.4–129.1 | 16,897–16,898 |
| plain | 1M | 264.00 | 143.4–143.5 | 8,449–8,451 |
| plain | 2M | 277.73 | 142.5–143.5 | 8,450 |
| vseg | 128K | 546.36 | 249.9–257.4 | 16,897–16,899 |
| vseg | 512K | 559.24 | 287.0–287.6 | 8,449–8,452 |
| vseg | 1M | 549.87 | 286.7–288.3 | 8,449–8,451 |
| vseg | 2M | **551.93** | 286.6–288.7 | 8,449–8,451 |

**判读**

- vseg@2M vs plain@128K = **2.04×**；vs plain@2M = **1.99×**；vseg 四个 chunk 全在 546–559µs 窄带 ⇒ chunk 对 vseg 无效。
- chunk≥256K 时 target n 减半（每 key 16 个 256KiB IO）⇒ target 单 IO 被夹在 256KiB；大 IO 不降时延、W9 反而升。
- 2× 是按字节的服务成本，不是每 IO 固定开销；单 target 配置调参到顶，转多 target。

## NOF-116（双 target · 400 keys · 128K 首测）

**测试条件**

- 环境：reader node2；master+etcd node4；vseg = target A（node3）+ target B（node4）；plain = 单 target B。
- 数据：plain 写 400 keys（16t/batch16）；vseg 写 400 keys（`--num_keys=200`/segment，T1）；两臂读同一批 400 个 key 的 LBA。
- vseg 配置：extent=50GiB、stripe=2MiB、member_count=2；plain 单 target。
- 读取：plain 3 遍、vseg 6 遍；T1、warmup=128、qpairs=4、verify=false、diag 关。
- 链路：plain 每 key 32×128KiB→B；vseg 每 key 2×2MiB child，每 target 16×128KiB。

**结果（µs）**

| 臂 | 每遍 P50 | 均值 | 中位 | W9（每 target） |
|---|---|---|---|---|
| plain（B） | 267.74 / 264.86 / 266.49 | **266.36** | 266.49 | **120.33** |
| vseg（A+B） | 300.09 / 461.35 / 284.93 / 290.85 / 324.15 / 280.17 | **323.59** | **295.47** | **157.3** |

- 比值：均值 **1.215×**、中位 **1.109×**、最好一遍 1.058×；W9 1.31×；461.35 为离群，去掉后均值 ~296（1.11×）。
- vseg 前 3 遍用错 `--num_keys=400`（每 segment 语义，产生 400 个失败样本），已作废，不在上表。

**判读**：双 target 把单 target 的 2.04× 压到 ~1.1×，未达 parity；剩余在 target 每 IO（157 vs 120）与每 target IO 数（16 vs 32）。

## NOF-117（双 target · 400 keys · 64K chunk）

**测试条件**

- 零写、零重启、零改码；复用 `vseg_nof116` 的 400 keys 数据与同一 master。
- 同会话 **128K / 64K 交替 3+3 遍**；读取参数同 NOF-116（T1/warmup128/qpairs4/verify=false/diag 关）。
- 64K 生效：`blocks_per_chunk` 128（128K 为 256），每 target n 从 ~8,449 变 ~16,897。
- 对照 plain：NOF-116 的同批 400 keys、plain 266.36µs/W9 120.33（非本会话同时测）。

**结果（µs）**

| 项 | vseg@128K | vseg@64K | 变化 |
|---|---|---|---|
| P50 三遍 | 303.75 / 291.37 / 286.59 | 272.27 / 294.54 / 293.91 | — |
| P50 均值 | 293.90 | **286.91** | −2.38% |
| P50 中位 | 291.37 | **293.91** | +0.9% |
| Avg / P90 均值 | 392.48 / 537.46 | 371.10 / 508.84 | −5.45% / −5.32% |
| target W9 | 157.58 | **130.50** | **−17.2%** |
| 每 target n | ~8,449 | ~16,897 | ×2 |
| 对 plain 266.36 的 P50 比值 | 1.10× | **1.077×（均值）/ ~1.10×（中位）** | — |

- 单遍 272.27（1.022×）达门槛，另两遍 294 未达 ⇒ 不判达标。
- 会话漂移：本会话 128K 基线 293.90 比 NOF-116 vseg 均值 323.59 低 9%，所以只做同会话交替对照。

**判读**：W9 明显改善但 P50 不动 ⇒ 队列深度/每 target IO 数不是 P50 差的主因，停止调 chunk；剩余 ~25µs 在客户端两 child 聚合/两跳，不在 target 单 IO。

## NOF-124（双 target · 60k · extent 50GiB · parity 验收）

**测试条件**

- vseg 臂：`vseg_nof123`，**59,931 keys**（NOF-123 写：60k、T1/batch1，69 个缺失）；extent=50GiB、3 个 vsegment；读 1 遍 60k queries（`--num_keys=30000`/segment）。
- plain 臂：`plain_nof124`，单 target B；写 60,000 keys（16t/batch16）；读 1 遍 60k keys。
- 读取两臂相同：T1、warmup=128、qpairs=4、verify=false、diag 关；每臂 1 遍。
- 链路：vseg 每 target 16×128KiB/key；plain 单 target 32×128KiB/key。
- 读墙钟：vseg 19s、plain 20s。

**结果（µs）**

| 指标 | vseg（59,931） | plain（60,000） | 比值 vseg/plain | 判据 ≤1.05 |
|---|---|---|---|---|
| **P50** | **246.32** | **255.06** | **0.966×** | ✅ |
| Avg | 252.35 | 256.74 | 0.983× | ✅ |
| P90 | 255.10 | 263.26 | 0.969× | ✅ |
| P99 | 361.82 | 274.62 | 1.317× | ✗ |
| Max | 57,788.40 | 2,443.73 | 23.6× | ✗ |
| Min | 81.45 | 242.03 | 0.336× | — |
| target W9avg | 40,410 / 40,330（A/B） | 44,450（B） | 0.909 / 0.907 | ✅ |
| failed | 69（0.115%） | 0 | — | — |

**判读**

- **P50/Avg/P90/W9 达到 parity；P99/Max 未达到**。
- 69 个缺失 key（type unknown、1× `ret=-704 OBJECT_NOT_FOUND`）可能污染尾部；补齐/剔除失败样本前，尾部差距不归因 vseg。
- 两臂写模式不同（vseg T1 / plain 16t），读取参数相同；本单只判读路径。

## NOF-125（双 target · 60k · extent 256GiB 一整块）

**测试条件**

- 只改 `--vsegment_member_extent_size`：50GiB（53,687,091,200）→ **256GiB（274,877,906,944）**；`member_count=2` ⇒ 逻辑 512GiB，60k×4MiB=234.375GiB 全装 1 个 vsegment。
- 其余同 NOF-124：stripe=2MiB、required_medium=nof、reserved_ratio=0、io_alignment=4096、slot=1、HA+oplog（etcd 64MiB）；target A/B 未重启；注册 B→A 各 512GiB。
- 数据：60,000 keys 全部可读（**0 缺失**），读结果不含 NOF-124 的缺失 key 污染。
- 读取：1 遍 60k queries（`--num_keys=30000`/segment），T1、warmup=128、qpairs=4、verify=false、diag 关；20s 墙钟。
- 对照：plain 用 NOF-124 的 255.06µs（**跨会话**，非本单同时测）；vseg 50G 用 NOF-124 的 246.32µs（跨会话）。

**结果（读，µs）**

| 指标 | NOF-125 vseg（256G） |
|---|---|
| queries / failed | 60,000 / **0** |
| Min | 250.54 |
| Avg | 278.06 |
| **P50** | **272.37** |
| P90 | 285.03 |
| P99 | 386.92 |
| Max | 60,862.44 |
| target W9avg（B/A） | 39,150 / 38,890 ns |
| 墙钟 | 20s |

| 对比（读） | P50 | Avg | P90 | P99 | W9 |
|---|---|---|---|---|---|
| vs plain 255.06（跨会话） | **1.068×（>1.05，未过）** | 1.083× | 1.083× | 1.409× | 0.881 / 0.875（更好） |
| vs vseg 246.32（50G，跨会话） | **+10.6%** | +10.2% | +11.7% | — | −3.1% / −3.6% |

- target 读 n（B/A）：841,329 / 822,083；该计数低于理论 60k×16=960,000，窗口口径不完整，**仅参考**。

**判读**

- **读侧未达 parity**（1.068×，阈值 267.81）。但单遍 + 跨会话，10.6% 的差异落在历史会话漂移（~9%）量级内，**不能归因 extent**。
- target W9 反而低 3%、端到端却高 10.6% ⇒ 劣化不在 target 单 IO；60k 数据完整（0 缺失），排除 NOF-124 的缺失 key 因素。
- 收口验证：NOF-126 同会话三臂（vseg256 复读 3 遍 → vseg50 重写+读 3 遍 → plain 重写+读 3 遍），判 extent 影响、同会话 parity 与 target n 计数真伪；结果待回执。

## 禁用比法（看数时注意）

1. **不同单不相减**：NOF-116 与 NOF-117 的 vseg 128K 差 9% 是会话漂移；NOF-124 与 NOF-125 的 10.6% 同属跨会话，不能当 extent 效应。
2. **不同 key 数不相减**：400 keys（113R/116/117）与 60k（124/125）不能算“改善了多少 µs”。
3. **W9 不是端到端**：它是 target 每 IO 执行窗口的滚动汇总；plain/vseg 的 IO 数不同，只作同结构对照。
4. **target n 不是完整 IO 总量**：理论 vseg 60k×16=960,000/target，实测 841k/822k（125）与 535k/515k（124），受窗口/连接口径影响，跨会话不可比。
5. **diag 数不作性能**：diag 开只用于归因，绝对时延会变大。
6. **vseg `--num_keys` 是每 segment**：400 keys 用 200、60k 用 30,000；用错会得到 800 queries/400 rpc_fail 的假数据。
7. **extent 不是 DRAM**：256GiB 是每 member 在 NoF segment 上的地址预留；每 target 注册 512GiB，256G/member 留一半余量。
