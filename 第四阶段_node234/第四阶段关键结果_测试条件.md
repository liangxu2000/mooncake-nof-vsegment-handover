# 第四阶段关键结果与测试条件（node2/3/4）

- 范围：NOF-113R（单 target 上限，背景）→ NOF-115（双 target 打通）→ NOF-116/117（400 keys）→ NOF-119A/120/121/122/123（写入墙）→ NOF-124（60k parity）→ NOF-125（一整块 vsegment，在途）。
- 原则：只写实测；每个数字带场景/口径；**跨单、跨会话的数字不相减、不混比**，原因写在 §5。
- 时延单位一律 **µs**；W9 单位 ns（target 侧每 IO 执行窗口）。
- 只用 node 标签，不写内网 IP。

## 1. 固定环境与参数（NOF-115 ~ NOF-125）

### 1.1 拓扑（用户 2026-11-26 确认）

| 角色 | 节点 | 说明 |
|---|---|---|
| reader / writer | **node2** | bench 客户端；元数据和数据都跨节点 |
| master + etcd | **node4** | RPC 50056、metrics 9006、HTTP metadata 8086 |
| target B | **node4** | 11 盘 RAID0、strip 256KiB、nsid1、端口 4457 |
| target A | **node3** | 11 盘 RAID0、strip 256KiB、nsid1、端口 4457；NQN `...urma-gpu-test-node3` / SN `URMAGPU0003` |
| vseg 形态 | 双远端 target | `member_count=2`，4MiB key → 2×2MiB child，分别落 A/B |
| plain 形态 | 单 target | 只用 node4 B |

### 1.2 vseg 配置（除注明外，全程不变）

| 参数 | 值 |
|---|---|
| `member_count` | 2（条带，不是副本；每 target 存 key 的一半） |
| `stripe_size` | 2 MiB |
| `member_extent_size` | **50 GiB**（NOF-115 ~ NOF-124）；**256 GiB**（NOF-125） |
| 每 vsegment 逻辑容量 | 50×2 = **100 GiB**（NOF-125：256×2 = **512 GiB**） |
| `required_medium` / `reserved_ratio` / `io_alignment` | nof / 0 / 4096 |
| `submaster_count` / slot | 1 / slot=1（`MC_STORE_PARTITION_SLOT_COUNT=1`） |
| HA / oplog | on（etcd；NOF-123 起 etcd `--max-request-bytes=67108864`，此前默认 2MiB） |
| `--oplog_batch_max_entries` | 1024（NOF-121 前）→ **64**（NOF-122 起） |

### 1.3 负载与读取口径（性能臂）

| 项 | 值 |
|---|---|
| key 大小 | 4 MiB |
| key 数 | 400（NOF-113R/115/116/117）；60,000（NOF-119B 起） |
| 应用层并发 | **T1 = threads=1 / batch=1**（一次一个 4MiB get；这是“单并发”的含义） |
| 链路并发 | `qpairs=4`；plain 每 key 32×128KiB 子 IO；vseg 每 target 16×128KiB（64K 臂为 32） |
| warmup | 128 keys（统计前顺序读 0..127，不计入延迟） |
| verify / diag | false / 关（性能臂）；diag 开只作归因，不作性能 |
| NoF 提交切片 | `MC_NOF_SUBMIT_CHUNK_BYTES` = 128KiB（默认）；NOF-117 另一臂 64KiB |
| vseg 的 `--num_keys` | **每 segment 的 key 数**：400 keys 用 200；60k 用 30,000 |
| 阅读顺序 | sequential |

### 1.4 两个指标的含义

- **端到端 P50/Avg/P90/P99/Max**：客户端 `get_into` 一次 4MiB 读的时延，含控制面 + 两个 child（vseg）/全部子 IO（plain）聚合。
- **W9**：target 侧每个 IO 的“执行窗口”滚动汇总（ns），**不是端到端**；两臂 IO 数不同，W9 只作同结构对照，不能单独当验收。
- 验收：**parity = vseg P50 与 W9 都 ≤ plain × 1.05**；2× 不可接受。

## 2. 结论总表（演进）

| 任务 | 场景 | vseg P50 | plain P50 | 比值 | 结论 |
|---|---|---|---|---|---|
| NOF-113R | 单 target、400 keys、128K chunk | 546.36 | 270.52 | **2.04×** | 单 target 配置调参到顶 |
| NOF-116 | 双 target、400 keys、128K | 323.59（均值） | 266.36 | **1.215×**（中位 1.109×） | 双 target 把 2× 压到 ~1.1× |
| NOF-117 | 双 target、400 keys、**64K** | 286.91（均值）/293.91（中位） | 266.36 | **1.077×** / ~1.10× | W9 降 17.2%，P50 不动 |
| NOF-124 | 双 target、**60k keys、128K** | **246.32** | **255.06** | **0.966×** | **P50/Avg/P90/W9 parity 达成**（50GiB/3vseg） |
| NOF-125 | 双 target、60k、**extent 256GiB 一整块** | **272.37** | 255.06（跨会话） | **1.068×** | 写侧全胜；读侧未达 parity（单遍跨会话） |

- NOF-113R→116→117 是 400 keys 的配置排查链；NOF-124 是 60k 的验收结果；NOF-125 是 extent 单变量实验。**117 与 124、124 与 125 都不能直接相减**（key 数、会话、数据、chunk/extent 均不同）。
- NOF-124 的 P99/Max 未平（1.317× / 23.6×），且有 69 个缺失 key，尾部暂不归因 vseg。
- NOF-125 的读侧差异（vs 124 +10.6%）落在历史会话漂移（~9%）量级内，**尚不能归因 extent**；NOF-126 同会话三臂复核中。

## 3. 逐单条件与结果

### NOF-113R（背景 · 单 target 配置上限 · 2026-11-25/26）

**条件**

- 环境：reader node2；master+etcd node4；**target 只有 node4 一个**（旧实例 2142228，NOF-119A 前）；cluster `vseg_nof107` / plain `plain` 已有 400 keys。
- 负载：400 keys × 4MiB；T1、warmup=128、qpairs=4、verify=false、diag 关；每臂 3 遍。
- 变量：`MC_NOF_SUBMIT_CHUNK_BYTES`；vseg 与 plain 同 LBA、同 IO 数对照。

**结果**

| 臂 | chunk | P50 | target W9 | target n |
|---|---|---|---|---|
| plain | 128K | **270.52** | 120.4–129.1 | 16,897–16,898 |
| plain | 1M | 264.00 | 143.4–143.5 | 8,449–8,451 |
| plain | 2M | 277.73 | 142.5–143.5 | 8,450 |
| vseg | 128K | 546.36 | 249.9–257.4 | 16,897–16,899 |
| vseg | 512K | 559.24 | 287.0–287.6 | 8,449–8,452 |
| vseg | 1M | 549.87 | 286.7–288.3 | 8,449–8,451 |
| vseg | 2M | **551.93** | 286.6–288.7 | 8,449–8,451 |

**判读**

- vseg@2M vs plain@128K = **2.04×**；vseg@2M vs plain@2M = **1.99×**；vseg 四个 chunk 全在 546–559 窄带 ⇒ **chunk 对 vseg 无效**。
- target 实际单 IO 被夹在 **256KiB**：chunk≥256K 时 target n 从 ~16,898 掉到 ~8,450（每 key 16 IO），大 IO 不降时延、W9 反而升。
- ⇒ 2× 是**每字节服务成本**，不是每 IO 固定开销；单 target 配置路径到顶，转多 target。

### NOF-116（双 target 400 keys 首测 · 2026-11-26）

**条件**

- plain 臂：`plain_nof116`（node4 单 target B），写 400 keys（16t/batch16），读 3 遍。

**结果**

| 臂 | 每遍 P50 | 均值 | 中位 | W9（每 target） |

| plain | 267.74 / 264.86 / 266.49 | **266.36** | 266.49 | **120.33** |

**判读**：双 target 把 2.03× 压到 ~1.1×；剩余在 target 每 IO（157 vs 120）和每 target IO 数（16 vs 32）。→ NOF-117 试 64K。

### NOF-117（64K chunk 对照 · 2026-11-26）

**条件**

- 零写、零重启、零改码；复用 `vseg_nof116` 与 400 keys 数据。

| P50 三遍 | 303.75 / 291.37 / 286.59 | 272.27 / 294.54 / 293.91 | — | 267.74 / 264.86 / 266.49 |

### NOF-121（补写 60k 撞 2MiB 事务墙 · 2026-11-26）

**条件**

- 复用 `vseg_nof120`（Keys=5,000），补写到 60,000；`--num_keys=30000`/segment；T1/batch1；oplog on、batch=1024。

**结果**

- 在 **25,647 keys** 处失败：34,353 failed，`ret=-1010`。
- etcd 单事务 **13,295,444 B > 默认 2,097,152 B**，`ResourceExhausted`；master 对同一超大批判无限重试（3784+ 次）。
- **不是总空间**：etcd dbSize 54.5MiB、oplog 23.89MiB、`/home` 余 1.1TiB。
- 25,647×4MiB=100.184GiB，刚越过单 vsegment 100GiB quota；但 vsegments=2 时 capacity 仍 100GiB、create_success=1（扩容路径可疑，未分离）。

**判读**：先试批大小（NOF-122）。

### NOF-122（batch 64 重试 · 2026-11-26）

**条件**

- 停 wedged `vseg_nof120` master；新 cluster `vseg_nof122`；`--oplog_batch_max_entries=64`（1024→64）；其余同 NOF-121；重写 60k。

**结果**

- 仍失败在 **25,632 keys**，事务仍 **13,322,832 B**（与 batch=1024 的 13,295,444B 差 0.2%）；`ResourceExhausted` 12,588。
- 源码确认：`VSegmentOpLogRecord.full_state=true` 的 payload 是 `PartitionVSegmentSnapshot`（每 key allocation ≈520B），**是单条 OpLogEntry，batch 拆不开**。
- 不是总空间：etcd 92MiB、`/home` 1.1TiB、`/cvm` 0.012MiB。

**判读**：batch 不是杠杆；根因是第 2 个 vsegment 创建时的 full-state 单事务。→ 抬 etcd 上限（NOF-123）。

## 5. 口径与禁用比法（很重要）

1. **不同单不相减**：NOF-116 的 vseg 323.59（400 keys、128K、不同会话）与 NOF-117 的 293.90 差 9%，是会话漂移；NOF-117 内部只用同会话 128K/64K 交替对照。
2. **不同 key 数不相减**：117（400 keys）与 124（60k keys）不能算“改善了 X µs”。
3. **W9 不是端到端**：它只是 target 每 IO 执行窗口的滚动汇总；两臂 IO 数不同（plain 32/key 单 target；vseg 16/target/key）。NOF-124 的 40.4 vs 44.45 可同结构对照，但不能单独当验收。
4. **diag 数不作性能**：diag 开只用于五段归因；绝对 P50 会变大（历史 +17.7%）。
5. **vseg `--num_keys` 是每 segment**：400 keys 用 200、60k 用 30,000；用错会得到“800 queries/400 rpc_fail”的假数据。
6. **写模式**：vseg 60k 是 T1/batch1（NOF-123），plain 60k 是 16t/batch16（NOF-124）；写时延不可直接比，读时延同参数可比。
7. **尾部**：NOF-124 的 P99/Max 受 69 个缺失 key 污染；未清洁前不归因 vseg。
8. **NOF-125 的 extent**：256GiB 是每个 member 在 NoF segment 上的地址预留，不是节点 DRAM；每 target 注册 512GiB，256G/member 留一半余量。
9. **target 读 n 不是完整 IO 总量**：理论应为 60k×16=960,000/target（vseg），但实测 NOF-125 为 841,329/822,083、NOF-124 为 535,330/515,570；该计数受 target 窗口/连接口径影响，**跨会话不可比**；NOF-125 的“+58%”因此不作事实采信，由 NOF-126 同会话逐遍复核。
