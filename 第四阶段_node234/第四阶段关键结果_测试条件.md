# 第四阶段时延测试结果（逐单条件 + 结果）

- 只收录**跑了读时延测试**的单：NOF-113R（单 target 背景）、NOF-116、NOF-117、NOF-124、NOF-125、NOF-126（同会话三臂）。
- **每个单只放本单自己的数据，一张表**；跨单对比单独放最后 §跨单对比，并注明参照单。
- 只放读时延，不放写入性能；时延单位 µs，W9 单位 ns（target 侧每 IO 执行窗口）。
- 名词：**vseg50** = `extent=50GiB/member`（逻辑 100GiB/vsegment，60k 占 3 个 vsegment）；**vseg256** = `extent=256GiB/member`（逻辑 512GiB，60k 装 1 个 vsegment）。代码/target/读写参数相同，只差 extent。
- 写入墙探针（NOF-115/118/119A/120–123）不属时延测试，见 `oplog写入墙跟踪.md`。

## 共用口径（所有单相同，除非单内另注）

| 项 | 值 |
|---|---|
| 拓扑 | reader/writer **node2**；master+etcd **node4**；plain 只用 target B（node4）；vseg 用 target A（node3）+ B（node4），`member_count=2` |
| target | 两 target 均 11 盘 RAID0、strip 256KiB、nsid1、端口 4457 |
| key / 数据 | 4MiB/key；400 keys（113R/116/117）；60,000 keys（124/125） |
| 读取并发 | **T1 = threads=1 / batch=1**（应用层一次一个 4MiB get） |
| 链路并发 | `qpairs=4`；plain 每 key 32×128KiB→单 target；vseg 每 key 2×2MiB child，每 target 16×128KiB（64K 臂为 32） |
| 其他 | warmup=128、verify=false、diag 关、sequential |
| vseg 配置 | `member_count=2 / stripe=2MiB / required_medium=nof / reserved_ratio=0 / io_alignment=4096 / submaster_count=1`；extent 见各单 |
| `--num_keys` | vseg 是**每 segment**：400 keys 用 200，60k 用 30,000 |
| 指标 | 端到端 Min/Avg/P50/P90/P99/Max；W9 = target 每 IO 执行窗口，**不是端到端** |
| 验收 | vseg P50 与 W9 均 ≤ plain×1.05；2× 不可接受 |

## NOF-113R（单 target · 400 keys · chunk 扫描）

**测试条件**

- 环境：reader node2；master+etcd node4；**只有 target B（node4，旧实例 2142228）**。
- 数据：400 keys × 4MiB 已存在；vseg `vseg_nof107`（单 target、extent=50GiB、member_count=1）；plain 同 400 keys。
- 负载：T1、warmup=128、qpairs=4、verify=false、diag 关；每臂 3 遍。
- 变量：`MC_NOF_SUBMIT_CHUNK_BYTES` = 128K / 512K / 1M / 2M；vseg 与 plain 读同一 LBA、同 IO 数。
- 链路：单 target；plain 与 vseg 每 key 32 个子 IO（128K 时）。

**本单结果（T1，µs；回执只给三遍合成值，历史数据无逐遍）**

| chunk | plain P50 | vseg P50 | vseg/plain | plain W9 | vseg W9 |
|---|---|---|---|---|---|
| 128K | 270.52 | 546.36 | **2.02×** | 120.4–129.1 | 249.9–257.4 |
| 512K | —（未跑） | 559.24 | — | — | 287.0–287.6 |
| 1M | 264.00 | 549.87 | 2.08× | 143.4–143.5 | 286.7–288.3 |
| 2M | 277.73 | **551.93** | 1.99× | 142.5–143.5 | 286.6–288.7 |

- target n/遍：128K 时 plain/vseg 均 ~16,897；≥512K 时 ~8,450。

**判读**

- 同 chunk 下 vseg/plain = 2.02×（128K）/ 2.08×（1M）/ 1.99×（2M）；vseg 四个 chunk 全在 546–559µs 窄带 ⇒ chunk 对 vseg 无效。
- chunk≥256K 时 target n 减半（每 key 16 个 256KiB IO）⇒ target 单 IO 被夹在 256KiB；大 IO 不降时延、W9 反而升。
- 2× 是按字节的服务成本，不是每 IO 固定开销；单 target 配置调参到顶，转多 target。

## NOF-116（双 target · 400 keys · 128K 首测）

**测试条件**

- 环境：reader node2；master+etcd node4；vseg = target A（node3）+ target B（node4）；plain = 单 target B。
- 数据：plain 写 400 keys（16t/batch16）；vseg 写 400 keys（`--num_keys=200`/segment，T1）；两臂读同一批 400 个 key 的 LBA。
- vseg 配置：extent=50GiB、stripe=2MiB、member_count=2；plain 单 target。
- 读取：plain 3 遍、vseg 6 遍；T1、warmup=128、qpairs=4、verify=false、diag 关。
- 链路：plain 每 key 32×128KiB→B；vseg 每 key 2×2MiB child，每 target 16×128KiB。

**本单结果（µs；逐遍原始值）**

| 项 | plain（单 target B） | vseg（A+B） |
|---|---|---|
| P50（逐遍） | 267.74 / 264.86 / 266.49 | 300.09 / 461.35 / 284.93 / 290.85 / 324.15 / 280.17 |
| target W9 | 120.33 | 157.3 |
| W9 比 | — | 1.31× |

- vseg 461.35 为离群；其余五遍 280.17–324.15。
- vseg 前 3 遍用错 `--num_keys=400`（每 segment 语义，产生 400 个失败样本），已作废，不在上表。

**判读**：plain 三遍 264.86–267.74，vseg 除离群外 280.17–324.15 ⇒ 双 target 把单 target 的 2.02× 压到约 1.05–1.22×，未达 parity；剩余在 target 每 IO（157 vs 120）与每 target IO 数（16 vs 32）。

## NOF-117（双 target · 400 keys · 128K vs 64K）

**测试条件**

- 零写、零重启、零改码；复用 `vseg_nof116` 的 400 keys 数据与同一 master。
- 同会话 **128K / 64K 交替 3+3 遍**；读取参数同 NOF-116（T1/warmup128/qpairs4/verify=false/diag 关）。
- 64K 生效：`blocks_per_chunk` 128（128K 为 256），每 target n 从 ~8,449 变 ~16,897。

**本单结果（µs；逐遍原始值，只有 vseg 数据）**

| 项 | vseg@128K | vseg@64K |
|---|---|---|
| P50（逐遍） | 303.75 / 291.37 / 286.59 | 272.27 / 294.54 / 293.91 |
| 逐遍比 64K/128K | — | 0.896 / 1.011 / 1.026 |
| target W9 | 157.58 | 130.50 |
| W9 比 | — | 0.828×（−17.2%） |
| 每 target n | ~8,449 | ~16,897 |

**判读**：P50 逐遍互有高低（0.896 / 1.011 / 1.026），没有整体下降；target W9 明显降低（157.58 → 130.50）⇒ 队列深度/每 target IO 数不是 P50 差的主因，停止调 chunk；剩余 ~25µs 在客户端两 child 聚合/两跳，不在 target 单 IO。

## NOF-124（双 target · 60k · extent 50GiB · parity 验收）

**测试条件**

- vseg 臂：`vseg_nof123`，**59,931 keys**（NOF-123 写入的数据，69 个缺失）；extent=50GiB、3 个 vsegment；读 1 遍 60k queries（`--num_keys=30000`/segment）。

**本单结果（µs）**

## NOF-126（双 target · 60k · 同会话三臂：plain / vseg50 / vseg256）

**测试条件**

- 同一会话、同一读取参数，顺序固定 A→B→C（后写覆盖前数据）。
- **A（vseg256）**：复用 NOF-125 的 60k 数据（vsegments=1），零写复读 3 遍。
- **B（vseg50）**：新 `vseg_nof126_50g`（extent=50GiB，其余同）；写 60,000 keys（T1/batch1，59,967 成功 / 33 缺失）；读 3 遍。
- **C（plain）**：`plain_nof126p`（单 target B）；写 60,000 keys（16t/batch16，60,000/0）；读 3 遍。
- 读取三臂相同：60k queries（`--num_keys=30000`/segment；plain 60k）、T1、warmup=128、qpairs=4、verify=false、diag 关；每臂 3 遍。
- 数据完整性：A 60,000/0 缺失；B 59,967（33 缺失，0.055%）；C 60,000/0。

**本单结果（µs；每臂只给区间，逐轮原始值在 `run/nof126_summary.txt` 备查）**

| 臂 | 轮数 | Avg 范围 | P50 范围 | P90 范围 | P99 范围 | failed |
|---|---|---|---|---|---|---|
| plain（C） | 3 | 241.90–265.05 | 242.86–262.50 | 251.13–271.74 | 264.46–296.04 | 0 |
| vseg50（B） | 3 | 259.87–277.69 | 254.51–272.75 | 262.90–285.33 | 369.29–400.94 | 33 |
| vseg256（A） | 3 | 268.98–275.73 | 260.74–266.47 | 274.06–280.61 | 369.98–386.94 | 0 |

- **P50 对 plain 的逐轮比**：vseg50 **1.023–1.048（3/3 ≤1.05）**；vseg256 **1.012–1.074（2/3 >1.05）**。
- **extent 影响**：vseg256/vseg50 的逐轮 P50 比在 **−2.6%～+3.8%**，小于各自臂内跨度 ⇒ **无显著影响**。
- NOF-125 的 272.37 高于 A 臂 P50 上限 266.47 ⇒ 会话偏高；其相对 NOF-124 的 +10.6% 主要是漂移。
- **“+58% IO”是窗口计数伪影**：target dump 的 n 是单个 dump 块内计数、不是累计；plain 第 3 遍同一个 60k 负载只有 1,034,594（前两遍 1,923,395 / 1,924,099）；同会话 vseg256 的 n（776k–824k）反而低于 vseg50（896k–962k）。不存在真实 IO 放大。
- vseg 每 IO 的 target W9 比 plain 低约 12%（39 vs 44µs，两臂一致）；端到端剩余差距在客户端聚合/两跳，不在 target 单 IO。
- 注：本单发生在用户定“一整块 256G”正式条件之前；当时 50G 逐轮全过、256G 两遍超，但**后续用户已定正式条件为一整块 vseg256，50G 仅历史对照（见 NOF-127）**。

## 禁用比法（看数时注意）

1. **不同单不相减**：NOF-116 与 NOF-117 的 vseg 128K 差 9% 是会话漂移；NOF-124 与 NOF-125 的 10.6% 同属跨会话，已被 NOF-126 同会话三臂证明为漂移（A 臂三遍 260.74/265.70/266.47 均低于 125 的 272.37），不能当 extent 效应。
2. **不同 key 数不相减**：400 keys（113R/116/117）与 60k（124/125/126）不能算“改善了多少 µs”。
3. **W9 不是端到端**：它是 target 每 IO 执行窗口的滚动汇总；plain/vseg 的 IO 数不同，只作同结构对照。
4. **target n 不是完整 IO 总量**：它是 target dump 的**单个块内计数，不是累计**；NOF-126 中同一 plain 臂第 3 遍 1,034,594 vs 前两遍 1,923,395/1,924,099 即伪影。NOF-125 的“+58%”不成立。
5. **diag 数不作性能**：diag 开只用于归因，绝对时延会变大。
6. **vseg `--num_keys` 是每 segment**：400 keys 用 200、60k 用 30,000；用错会得到 800 queries/400 rpc_fail 的假数据。
7. **extent 不是 DRAM**：256GiB 是每 member 在 NoF segment 上的地址预留；每 target 注册 512GiB，256G/member 留一半余量。
8. **同会话三臂才是直接对照**：NOF-126 是唯一在同一会话里同时测 plain / vseg50 / vseg256 的单；其余单为单臂或跨会话参照。
