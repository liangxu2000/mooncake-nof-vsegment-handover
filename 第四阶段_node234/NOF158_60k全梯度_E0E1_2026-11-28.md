# NOF-158 60k 全梯度：4M → 128K × E0/E1（plain NoF + null bdev）

- 日期：2026-11-28
- 性质：**诊断**（60,000 keys、null bdev、diag-on），不写正式表
- 目的：把 NOF-155 的全梯度在 **60,000 keys** 下重跑，按 NOF-155 的格式给出每个尺寸的 target 拆解表 + 端到端拆解表，验证 400-key 的结论是否在 60k 成立。

> **NOF-159 复测更新（2026-11-28）**：512K E1 恢复正常 **16.7µs**（NOF-158 的 49.0 是慢化窗口内的时段状态，**异常撤回**）；128K target E1 快 **9.6µs/IO** 稳定，但 P50 方向不稳定（NOF-159 +47.0 反向），**128K 以 target t/IO 为准**。详见 `NOF159_512K_128K_复测_2026-11-28.md`。**本文件 512K/128K 的数值表已用 NOF-159 复测值替换；其余尺寸仍为 NOF-158 原始数据。**

---

## 结论摘要

- **26/26 遍 failed=0**；拆包自证 100%：`sub_ios=N`、`blocks=chunk/512`、read_ops=60,128×N；写 60,000 keys、`evicted=0`。
- **target 侧 6/6 尺寸与 400-key 一致**：target 单 IO 随拆细下降（E0 **88.7→38.1µs，−57%**），每 key 串行累加暴涨（E0 **88.7→1219µs，13.7×**），端到端 P50 基本不降（E0 **238→276µs**、E1 **176→323µs**；E1 的 128K P50 受 wait 抖动，不稳定）。
- **E1 的 target 优势（t/IO）6/6 尺寸复现**；**P50 优势不稳定**：512K 在 NOF-159 为 **−70.0**（NOF-158 的 +15.8 是慢化窗口），128K 在 NOF-157/158 为 −42.5/−49.2、NOF-159 **反转为 +47.0**（客户端 wait 抖动）。
- **512K E1 异常撤回**：NOF-159 三遍 **17.5/16.7/16.6**（E0 46.9）；NOF-158 的 49.0 是该尺寸整臂落入慢化窗口的时段状态，不是尺寸效应。
- **6/26 遍（23%）出现间歇性慢化**：target push 升至正常 1.9–2.3×，客户端 wait/read/P50 同步升高；已交叉核对 target n，不是对齐错误。报告用「剔除 SLOW 后中位」为主、另给「含 SLOW」敏感性，不丢弃数据。
- **慢化不专属 E0**：seq26（E1）target 88.6µs，与正常 E0 同量级 ⇒ “快/慢组”不是 EID 固有属性，而是随时间出现的 target push 状态；NOF-153 的 E0/E1 差只在正常窗口成立。
- **128K 的 400-key 17.4µs 作废**；60k 的 **target Δ 稳定 −9.6µs/IO**，但 **P50 不稳定**（NOF-157 −42.5、NOF-158 −49.2、NOF-159 +47.0）⇒ 128K 不能用 P50 臂间差下结论，以 target t/IO 为准。
- **拆细仍不是 T1 优化**：60k 下 128K 比 4M 慢（E0 P50 275.8 vs 238.1；E1 P50 322.7 vs 176.3，E1 的 P50 受 wait 抖动，以 target 为准）。

## 二、SLOW 慢化事件（必须先知）

26 遍中有 **6 遍（23%）** 被标记为 SLOW：target push JFC 升至正常 1.9–2.3×，客户端 wait/read/P50 同步升高；测试 Agent 逐块核对 target n（60134/481031 等）正确，**不是窗口对齐错误，是真实事件**。

处理方式：

- **主表 = 剔除 SLOW 后的中位**；每张表标出逐遍值与 `*` 标记。

## 五、判读

### 5.1 拆得越细，target 降多少、端到端降多少

- **target 单 IO（E0）**：88.7→38.1µs（−57%），单调下降；与 400-key 的 88.6→37.5 高度一致（512K E0 60k 46.9 vs 400k 46.0 略高）。
- **每 key target 串行累加（E0）**：88.7→1219µs（13.7×），IO 数 1→32 放大固定开销。
- **端到端 P50（E0）**：238→279µs，120µs 区间内波动，**没有一档比 4M 更快**；E1 176→230µs。
- **E1 的 target 优势（t/IO）6/6 尺寸复现**；**P50 优势不稳定**：4M +61.7、2M +37.7、1M +61.0、256K +53.5 仍成立；**512K 在 NOF-159 为 −70.0（NOF-158 的 +15.8 是慢化窗口）；128K 在 NOF-157/158 为 −42.5/−49.2、NOF-159 反转为 +47.0（客户端 wait 抖动）**。128K 不能看 P50，应以 target Δ−9.6 为准。

### 5.2 差额去哪了

- `res=read−N×t/IO` 从 4M 的 +44.8 变到 128K 的 −1039.2 ⇒ **N 个 IO 在 4 个 qpair 上深度重叠**，target 串行累加没有落到墙钟。
- 但 `read` 仍随 N 增长（E0 133.5→184.0，E1 74.5→138.0），`completion_wait` 增长更明显（E0 120.5→171.0，E1 63.0→128.0）；每 key 墙钟的两个大项是 query（~85µs）和 read 内的 wait。
- 结论与 400-key 相同：**target 单 IO 的收益被“更多 IO 的提交/完成/排队开销”抵消，且抵消量大于收益**；不是“收益被弱化”，而是端到端没有净收益。
- 没有 per-IO 客户端时间戳，无法把增长精确拆成“网络在飞”与“框架开销”；`read_us−target_us` 在 N>1 时不是纯网络。

### 5.3 512K·E1 异常（已由 NOF-159 撤回）

- NOF-158：E1 **48.9/49.1**（两遍高度一致），E0 正常 50.2；Δ(E0−E1)=+1.2µs，P50 Δ=+15.8。
- 400-key：E1 16.5，E0 46.0，Δ=+29.5，P50 Δ=+46.8。
- **NOF-159 复测（0 SLOW、3 正常遍/臂）**：E1 **17.5/16.7/16.6**，E0 **46.9**；target Δ **−30.2**，P50 Δ **−70.0** ⇒ 与 400-key 一致。
- **判决：NOF-158 的 49.0 是慢化窗口内的时段状态，不是尺寸效应；“512K 尺寸异常”撤回**。512K E1 正常，可作为 E1 收益点。
- 这说明 NOF-158 的 6/26 慢化不仅影响单遍，**可能让一个尺寸的整臂（E0+E1）落进慢化窗口**；后续必须 ≥3 个正常遍 + 慢化检测。

### 5.4 SLOW 事件对 E0/E1 归因的影响

- 6/26 遍慢化：target push 1.9–2.3×，客户端 wait/read/P50 同步升高；4 遍 E0、2 遍 E1。
- **seq26（E1）慢到 88.6µs，与正常 E0 同量级** ⇒ “E1 总是快、E0 总是慢”不成立；存在随时间出现的 target push 慢化状态，E0/E1 都可能中招。
- **512K E1 的 49.0 也是慢化窗口的后果**：NOF-159 在正常窗口三遍 17.5/16.7/16.6，E0 46.9；说明慢化可以让一个尺寸的整臂落进慢窗口，单遍/两遍的“尺寸异常”不可信。
- NOF-153 的 E0/E1 55µs 差在**正常窗口**成立（target 侧 6/6 尺寸复现），但不能当成 EID 的固定属性；E1 作为部署旋钮时，需要慢化检测/多遍中位，否则单遍可能把慢化状态误判成 EID 差异。
- 慢化根因未验证；target JFC 调参需重启，暂不做。
