# 第四阶段 E0 / E1 关键结果（2026-11-27）

## 结论摘要

- **E0 正式结果（NOF-127）**：vsegment/plain P50 **1.034×**、Avg 1.040×、P90 1.046×，parity 达成；P99 1.371× 未达；无 2×。
- **E1 T1 单并发（NOF-143，诊断）**：vsegment **230.31µs** vs plain **232.93µs（0.989×）**；P99 1.438× 仍差；不进正式表。
- **E1 高并发（NOF-141/142）**：plain 吞吐 **+48.31%**、vsegment **+101.11%**（保守 +91.58%）；是带宽优化，不是 T1 单 key 时延。
- **打点拆解（NOF-144/146/147/148）**：vsegment/plain 分段结构几乎重合，vsegment 只多 2µs resolve；客户端残差 39/54µs；16µs 是 key 聚合，不是 child skew。

## 三、E1 高并发（16t/batch16）下 vsegment vs plain

**条件**：60k×4MiB、vsegment 一整块（256GiB/member，m=2/stripe=2MiB）、plain 单 target B；16t/batch16、warmup128、qpairs4、verify=false、diag 关；E1（bench 客户端 `SPDK_URMA_EID_INDEX=1`，target 保持 EID0）；每臂 8 遍。

| 指标 | vsegment | plain | 比值（vseg/plain） |
|---|---|---|---|
| 吞吐（MiB/s） | **91,481.57** | **71,082.26** | **1.287×** |
| 批 Avg（µs） | 11,210.5 | 14,351.2 | 0.781× |
| 批 P50（µs） | **11,322.9** | **14,341.1** | **0.790×** |
| 批 P90（µs） | 12,065.0 | 14,819.6 | 0.814× |
| 批 P99（µs） | 12,863.9 | 15,696.5 | 0.820× |
| failed | 0 | 0 | — |

**批是什么意思**

- `batch_size=16`：一批 = **16 个 query × 4MiB = 64MiB**。
- 批 Avg/P50/P90/P99 是**一个 64MiB 批次**的时延，不是单个 4MiB key 的时延；不能与 T1 的 230µs 直接比。
- T1 P50 230µs 是“一次读 1 个 4MiB key”；批 P50 11.3ms 是“一次读 16 个 key、16 线程同时跑”的批次时延。

**同会话 E1/E0（真正 A/B）**

| 数据 | E0 吞吐 | E1 吞吐 | E1/E0 |
|---|---|---|---|
| plain | 47,927.44 MiB/s | 71,082.26 MiB/s | **1.483（+48.31%）** |
| vsegment | 45,488.34 MiB/s | 91,481.57 MiB/s | **2.011（+101.11%；保守 1.916 / +91.58%）** |

- vsegment E0 有一个离群遍（seq5），因此给保守值 +91.58%。
- **vsegment vs plain 这张是跨会话**（NOF-142 vs NOF-141），只作量级参考；同会话 A/B 看 E1/E0 表。
- 结论：E1 在高并发下是明确的**带宽优化**；不是 T1 单 key 时延优化。

## 四、打点拆解（E1，diag-on）

```
一次 vsegment 4MiB 读 ≈261µs
├─ 元数据 query 89µs（34%）
└─ 数据面 169µs（65%）
    ├─ target 设备执行 44–45µs
    └─ 客户端/网络 ≈124µs
        ├─ 排队/派发 11µs
        ├─ 提交两半 9.5µs
        ├─ 等两半 + 拼起来 16µs
        └─ drain 内 target 之外 ≈60µs + prepare/未归因 ≈14µs
```

| 项（µs） | plain | vsegment |
|---|---|---|
| query | 83 | 89 |
| 数据面 | 176 | 169 |
| total | 258 | 261 |
| 残差 cw−drain | 54 | 39 |
| 最大项 | submit_span 26.8 | 两 child 聚合 16 |

**判读**

- **vsegment/plain 分段结构几乎重合**；vsegment 只多 **2µs `vsegment_resolve`**，不多付数据面成本。
- **16µs 不是 child skew**（两 child 完成差 24.4µs 已含在数据搬运里），而是 **key 聚合**（cw 158 − 最慢 child task total 143 = 15µs）。
- `child.get()` 串行在 `transfer_task.cpp:2455-2461`；两 half 提交串行在 `2548-2558`；child1 比 child0 晚约 10µs 起步，76.2% 场景 child1 最慢。
- plain 的最大项是 **submit_span 26.8µs**（32 次 128KiB 串行提交）；vsegment 的最大项是 **两 child 聚合 16µs**。
- 本拆解为 **diag-on**：绝对值比 diag-off 膨胀约 14%，只看结构/占比；plain 与 vsegment 分段来自 NOF-144/146 两个会话，只比结构，不比绝对值。

## 五、口径说明（汇报时请保留）

1. **E0 是正式结果**；E1 T1 是诊断，不能替代 E0 正式表。若要把 E1 定为正式口径，需要再做一次 E1-only 的正式 A/B（ABBA、完整行、多遍）。
2. **E1 高并发是带宽优化**；批时延是 16×4MiB/批，不是单 key 时延。
3. **diag-on 拆解**只用于看结构/占比；绝对值受诊断开销影响，不进正式表。
4. 所有时延单位为 µs；W9 是 target 单 IO 执行窗口，不是端到端。
