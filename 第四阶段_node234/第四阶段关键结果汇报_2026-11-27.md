# 第四阶段关键结果汇报（2026-11-27）

## 一、结论

**先讲问题**：正式条件下 **P99 仍为 vsegment/plain = 1.371×**（376.69 vs 274.85µs），未达 ≤1.05；P50/Avg/P90 已达 parity，全程没有出现 2×。

**一句话结论**：60k×4MiB、一整块 vsegment、T1 正式条件下，vsegment P50 **257.01µs** vs plain **248.51µs = 1.034×**，Avg 1.040×、P90 1.046×（均 ≤1.05），**读时延 parity 达成**；P99 1.371× 未达；无 2×。

## 二、测试条件

| 项 | 口径 |
|---|---|
| 数据 | 60,000 keys × 4MiB（234.375GiB） |
| vsegment | 一整块：`extent=256GiB/member`（逻辑 512GiB），`vsegments=1`；`member_count=2 / stripe=2MiB` |
| plain | 单 target B（node4） |
| 拓扑 | reader node2；master+etcd node4；vsegment 用 target A（node3）+ target B（node4）；plain 只用 B |
| 读取 | T1（threads=1 / batch=1）、warmup=128、qpairs=4、verify=false、diag 关、sequential；每轮只读一遍 60k（≈20s，不循环） |
| 聚合 | Avg = 各轮均值；P50/P90/P99 = 各轮同分位中位（`测试结果聚合方法_20261112`） |
| 验收 | vsegment P50 与 target W9 ≤ plain×1.05；2× 不可接受 |

| 指标（µs） | vsegment | plain | vseg/plain |

- P50/Avg/P90 全部 ≤1.05；P99 未达；无 2×。
- 两臂 Avg spread 6.2% / 6.4%，为同窗口共同时间漂移，<10%，仍进正式表。

### target W9 汇总（target 侧单 IO 执行窗口，µs）

| 单（环境） | 端到端 P50（vseg / plain） | target W9 vseg | target W9 plain | W9 比 |
|---|---|---|---|---|
| **NOF-127 正式**（6+6 轮） | 257.01 / 248.51µs = **1.034×** | **39.19 / 39.22µs** | **44.17–44.22µs** | **≈0.887** |
| **NOF-129/130 同环境**（10+10 轮） | 260.59 / 252.08µs = **1.034×** | **39.62µs** | **47.63µs** | **0.832** |
| **NOF-134**（2-member，q4/q1 诊断） | V4 264.48 / plain 254.13µs = 1.041× | **39–40µs** | **47.4µs** | 0.82–0.84 |

- W9 是 target 侧每 IO 执行窗口（µs），**不是端到端**；不含客户端 query/submit/wait、两跳网络和 child 聚合。
- 两臂每 key 的 target IO 数不同：plain 单 target 32×128KiB；vsegment 每 target 16×128KiB（两个 target 合计 32）⇒ 只作同结构对照，不能当精确加速比。
- 方向一致：vsegment 的 target 单 IO 更短（W9 低 11–17%），端到端 P50 仍慢 3.4% ⇒ 剩余差距在客户端聚合/两跳路径，不在 target 执行段；W9 验收线（vseg ≤ plain×1.05）通过。

## 五、关键闭环

### 1. 旧 400-key 的 2× 未复现

- 当前环境 m=1、一整块、只读前 400 keys：V400/P400 P50 **261.00 vs 266.30µs = 0.980×**，Avg 1.003×、P90 0.960×、P99 1.020×，四项均在 0.960–1.020。
- 旧 NOF-113R 的 2× **551.93 / 270.52µs** 是旧 target 2142228（W9 286.6–288.7µs）+ `extent=64MiB/member=1`（400 keys 跨约 25 个 vsegment）的历史账，不是 400-key 规模本身。

### 2. 写入墙已解决

- etcd `--max-request-bytes=64MiB` + 一整块 vsegment 后，60k 写入 **60,000/0 failed**，`vsegments` 全程 1，无 13–31MB full-state。
- 恢复仍需要 64MiB；该配置不可撤。

### 3. P99 是结构性剩余

- vsegment 的 target 单 IO 反而更快（W9 约 39µs vs plain 44–48µs），端到端差额在客户端聚合/两跳路径。
- 已排除的旋钮：qpair、worker、chunk、stripe、分区/布局、extent、task 拆分、q1、EID（`MC_EID_INDEX` 与 `SPDK_URMA_EID_INDEX`）均无稳定收益。
- 在“不改 vsegment 逻辑代码、不加第三 target、master 留远端”的约束下，没有剩余合法旋钮。

## 六、SPDK_URMA_EID_INDEX 0→1 测试（T1 与高并发）

**背景**：`MC_EID_INDEX` 是 Mooncake Transfer Engine 内存通道的 EID，NoF 数据面不走它；NoF 走 SPDK NVMe-oF URMA，对应旋钮是 `SPDK_URMA_EID_INDEX`。本测试只改 bench 客户端该 env，target 保持 EID0、不重启。

**条件**：plain 60k；T1（threads=1 / batch=1）、warmup=128、qpairs=4、verify=false、diag 关、sequential；E0→E1 交替各 3 遍，每遍一遍 60k（≈20s）；`MC_EID_INDEX` unset；六遍 `/proc/<pid>/environ` 均自证 env 到位。

**结果（µs；Avg=各遍均值、分位=各遍同分位中位）**

| 指标 | E0（EID 0） | E1（EID 1） | E1/E0 |
|---|---|---|---|
| Avg | 261.23 | 247.51 | 0.947 |
| P50 | 258.67 | 244.86 | 0.947 |
| P90 | 268.36 | 256.23 | 0.955 |
| P99 | 288.07 | 272.49 | 0.946 |
| P50 spread | 5.2% | 6.5% | — |
| failed | 0 | 0 | — |

- 配对差（同对 E1−E0）：**+0.18% / −7.75% / −8.56%**；E1 始终后跑。
- 表面 E1 低 5.34%，但 **小于 E1 自身 P50 spread 6.5%**；配对差不一致，且与向下时间漂移一致 ⇒ **无稳固 EID 效应**。
- E0 中位 258.67 比正式 plain 基线 252–254 高 2–3%，本轮整体有漂移。
- T1 结论：`SPDK_URMA_EID_INDEX` 0→1 无稳定收益（时间漂移）。

### 高并发 16t/batch16（NOF-141）

**条件**：plain 60k；16t/batch16、warmup=128、qpairs=4、verify=false、diag 关、sequential；E0→E1 / E1→E0 交替 4 组，每臂 8 遍；只改 bench 客户端 env，target 保持 EID0。

**结果（吞吐为主指标；时延为批时延，仅诊断）**

| 指标 | E0（8 遍） | E1（8 遍） | E1/E0 |
|---|---|---|---|
| 吞吐 | **47,927.44 MiB/s**（spread 0.20%） | **71,082.26 MiB/s**（spread 4.17%） | **1.483（+48.31%）** |
| Avg（批） | 21,287.1µs | 14,351.2µs | 0.674 |
| P50（批） | 21,334.5µs | 14,341.1µs | 0.672 |
| P90（批） | 21,655.0µs | 14,819.6µs | 0.684 |
| P99（批） | 22,062.1µs | 15,696.5µs | 0.711 |

- 平衡配对：E0 先跑 4 块均值 **+49.24%**；E1 先跑 4 块均值 **+47.39%**；**8/8 块 E1 更快（最低 +45.37%）** ⇒ EID 效应成立，不是时间漂移。
- 批时延 14–21ms（16×4MiB/批），**不可与 T1/batch1（P50≈252–254µs）比**。
- **结论：`SPDK_URMA_EID_INDEX=1` 在高并发下有显著带宽收益（+48.31%），但不是 T1 单 key 时延优化；正式结果不变。vsegment 高并发复核（NOF-142）待执行。**

## 七、结论与建议

- 读时延按验收口径**已达 parity**（P50 1.034× / Avg 1.040× / P90 1.046×），无 2×；可按这个结果收口汇报。
- P99 1.371× 未达，属结构性；若要继续追，只能松开一条约束（改 vsegment 逻辑代码，或加第三 target），需要另立阶段。

## 附：口径说明

- 时延均为端到端 µs；W9 是 target 每 IO 执行窗口（单位 µs），不是端到端。
- 跨批次/跨会话数字不相减；正式结果以 NOF-127 为准，同环境表作复核。
- EID 等探索结果只用于排除旋钮，不并入本汇报主表。
